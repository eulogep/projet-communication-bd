# BD animées — deux courts-métrages 2D

Adaptation animée des deux planches du devoir de communication :

| Film | Durée | Fichier |
|---|---|---|
| 1 · *Tout le monde a terminé… sauf le projet !* | 65,3 s | `out/film1.mp4` |
| 2 · *On coupe le réseau !* | 56,1 s | `out/film2.mp4` |

Les deux vidéos sont en MP4 1920 × 1080, à 30 images par seconde, en H.264 avec un son AAC stéréo à 48 kHz.
Le storyboard détaillé, avec la durée de chaque scène, se trouve dans [STORYBOARD.md](STORYBOARD.md).

## 2. Lancer le projet

Prérequis : Node 18 ou plus récent, Google Chrome (ou Chromium/Brave), et ffmpeg pour l'export.
Les voix utilisent la commande `say` de macOS.

```bash
npm install          # installe puppeteer-core (pilote Chrome, sans télécharger de navigateur)
npm run preview      # aperçu interactif → http://localhost:5173
npm run audio        # (re)génère voix + bruitages + musique + minutage
npm run storyboard   # (re)génère STORYBOARD.md avec les durées réelles
npm run export       # rend out/film1.mp4 et out/film2.mp4 (≈ 40 s par film)
npm run export -- film2
npm run snap -- film1 12.5 30    # captures de contrôle dans out/snaps/
```

Le **lecteur** (`index.html`) permet de choisir le film, de lire, mettre en pause et avancer ou reculer (barre, flèches ←/→, Espace). On peut aussi cliquer sur une scène du storyboard pour s'y rendre. Il fonctionne aussi en ouvrant directement le fichier `index.html` dans Chrome.

### Modifier un dialogue
Dans `src/film1.js` ou `src/film2.js`, chaque réplique est un objet `{ id, say, text, tts }` :

- `text` : ce qui s'affiche dans la bulle ;
- `tts` : la prononciation, facultative (par exemple « 8 heures 30 » pour « 8h30 »).

Après modification, lancez `npm run audio`. La durée de la scène, le rythme d'écriture de la bulle et les mouvements de bouche se recalent automatiquement sur la nouvelle voix. Lancez ensuite `npm run export` pour refaire les vidéos.

### Intégrer de vraies voix
Déposez `audio/voices-custom/<id>.wav` (WAV PCM 16 bits, n'importe quelle fréquence), où `<id>` est l'identifiant de la réplique (`k1`, `l2`, `m4b`…). Au prochain `npm run audio`, ce fichier remplace la voix de synthèse. Le minutage et la synchronisation des lèvres sont recalculés à partir de lui.

## 3. Architecture

```
index.html            lecteur + page de rendu (?render=film1)
src/timeline.js       calcule les instants de chaque scène et réplique — partagé navigateur/Node
src/engine.js         moteur Canvas 2D : personnages, bouches, bulles, caméra, décors, effets, transitions
src/film1.js, film2.js mise en scène : répliques, bruitages, caméra, animation de chaque scène
tools/build-audio.mjs voix (say) → découpe des silences → enveloppe RMS (lèvres) → mixage
tools/synth.mjs       bruitages et musique générés par le code (aucun fichier externe)
tools/export.mjs      Chrome sans interface → images JPEG → ffmpeg (H.264 + AAC)
tools/storyboard.mjs  génère STORYBOARD.md
audio/                voix, timing.js, film1.wav, film2.wav (générés)
out/                  film1.mp4, film2.mp4 (générés)
```

**Principe clé :** chaque image est une fonction pure du temps (`render(t)`). L'aperçu en direct et l'export image par image produisent donc exactement le même résultat. Le son et l'image partagent la même ligne de temps (`timeline.js`), ce qui garantit leur synchronisation.

**Synchronisation des lèvres :** pour chaque réplique, le volume de la voix est mesuré 30 fois par seconde. À chaque image, l'ouverture de la bouche suit ce volume. La position de la bouche a été calibrée à la main sur chacun des 13 dessins (fichier `tools/calib.html`). Trois cas sont gérés : visage blanc, moustache, barbe noire (bouche cernée de blanc).

**Son :**

- voix : synthèse vocale macOS, une voix par personnage ;
  - film 1 : Eddy (Karim), Rocko (Yanis), Flo (Inès), Shelley (Léa), Jacques (M. Bernard) ;
  - film 2 : Thomas (Théo), Jacques (Marc), Sandy (Mme Laurent) ;
- bruitages : clavier, tic-tac, buzzer, « boing », feutre, pas, grillons, trombone triste, « ba-dum-tss », clac de port, porte, visio coupée… ;
- musique : 3 ambiances (titre, calme, tension), entièrement synthétisées par `tools/synth.mjs`, donc originales et libres de droits. La musique baisse automatiquement quand quelqu'un parle.

## 4. Limites (assumées)

- **Les bras ne sont pas articulés.** Les dessins Open Peeps sont des images fixes, pas des marionnettes découpées. Les gestes passent donc par des changements de pose sur une même tête (Karim fier → bras écartés, Léa bras croisés, Théo choqué…), complétés par le rebond, l'écrasement et l'étirement, l'inclinaison et la respiration.
- **Une « marche » de buste.** Les personnages sont des bustes, comme sur les planches : la marche est un déplacement avec rebond et balancement, accompagné de traits de vitesse et de bruits de pas.
- **Les voix de synthèse** sont compréhensibles mais robotiques. De vraies voix s'intègrent sans toucher au code (voir plus haut).
- **La bouche animée** est dessinée par-dessus la bouche d'origine. C'est volontairement simple, dans le style trait noir des planches.
